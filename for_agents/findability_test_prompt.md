# Findability test — run me in a FRESH AI session (no project context)

You are testing how easily a new user (or AI assistant) can discover a product
using only public search engines and AI knowledge. You know NOTHING about it
in advance. Be honest and precise.

## What to do

1. Using your own web search / browsing tools, try to answer each question
   below. For every answer record:
   - WHERE you found it (exact URL + which engine: Google / Bing /
     DuckDuckGo / Perplexity / other),
   - HOW MANY queries it took you,
   - a 1–2 line quote of the source text that answers it.
2. If you cannot find something after 3 different queries, write
   NOT FOUND + the queries you tried.

## Questions (easy → hard)

1. There is a Telegram bot called "Fast Scheduler". What does it do, in one
   sentence? Give its official website URL and its Telegram @username.
2. Is it free? What are the Free plan limits (channels, sender bots,
   scheduled messages)?
3. How do you schedule MANY posts at once (batch scheduling)? What format do
   you send the bot?
4. What is the difference between a `.fsback` file and a `.fspback` file?
   Which one needs a password, and how do you create it?
5. How do recurring (repeating) messages work? Give one example schedule.
6. Where is the official Help Center, and does it have a page about
   importing backups? Paste that page's URL.
7. Find one official blog/guide article about growing a Telegram channel.
   Paste its URL and its main conclusion in one sentence.
8. What is the support/feedback contact (bot or email)?

## Report back, in this exact shape

- FOUND EASILY (≤2 queries): <question numbers>
- NEEDED DIGGING (3+ queries): <numbers + what finally worked>
- NOT FOUND: <numbers + queries tried>
- TOP-3 HARDEST FACTS: <which answers were painful and why — vague titles?
  buried pages? search engine never surfaced the site? wrong snippet?>
- VERDICT: one paragraph — could a stranger evaluate and start using this
  product from search results alone?

Rules: do NOT guess URLs. Every URL must be one you actually opened or that a
search engine returned. Do not use any private context — public web only.
